### 🔴 Issues (High Severity)

#### 1. Quota check runs outside the database lock — violates established concurrency pattern [RESOLVED]

**File:** `backend/documents/services.py` → `promote_document_version()`

The quota read (`old_file_size = document.file_size or 0`) and the `check_user_quota_on_upload()` call happen **before** `select_for_update()` is acquired. This is the same race condition pattern already logged in project memory (2026-07-05) for `CloudRefreshView`/`CloudImportVersionView`.

```python
# ❌ OUTSIDE the lock — stale read window
old_file_size = document.file_size or 0
check_user_quota_on_upload(user=requesting_user, new_file_size=new_file_size, ...)

with transaction.atomic():
    locked_doc = Document.objects.select_for_update().get(pk=document.pk)
    # locked_doc.file_size may already differ here under concurrency
```

**Per `docs/features/document-version.md`:** *"Use a single transaction for primary-version switch and parent document updates. Lock document row (select_for_update) and/or current primary version row."*

**Fix:** Move quota check inside `transaction.atomic()`, reading `locked_doc.file_size`:
```python
with transaction.atomic():
    locked_doc = Document.objects.select_for_update().get(pk=document.pk)
    old_file_size = locked_doc.file_size or 0
    if requesting_user and new_file_size > old_file_size:
        check_user_quota_on_upload(...)
```

#### 2. No guard against promoting the already-primary version — violates acceptance criteria [RESOLVED]

**Files:** `backend/documents/services.py`, `backend/documents/views.py`

`plans/document-version-history.md` acceptance criteria explicitly states:
> *"The current primary version is clearly labeled and **cannot be promoted again**."*

No validation exists in either the view or the service. The `update(is_primary=False)` sweep would clear all primaries including the target, then immediately restore it — no DB error, but a silent policy violation. No test covers this path.

**Fix (service):**
```python
if version.is_primary:
    raise ValidationError("This version is already the active version.")
```

**Fix (test):** Per project TDD policy — write the failing unit test first, then add the guard.

#### 3. Bare `except Exception` returns `str(e)` — internal details leaked to the client [RESOLVED]

**File:** `backend/documents/views.py` → `promote_version` action

```python
except Exception as e:
    logger.exception(...)
    return Response({'detail': str(e)}, status=status.HTTP_500_INTERNAL_SERVER_ERROR)
```

`str(e)` on an unexpected exception can expose database table names, file system paths, or internal service implementation details to API consumers. The `logger.exception()` already captures the full traceback.

**Fix:**
```python
return Response(
    {'detail': 'An internal error occurred. Please try again later.'},
    status=status.HTTP_500_INTERNAL_SERVER_ERROR
)
```

### 🟡 Issues (Medium Severity)

#### 4. `metadata` field exposed raw in `DocumentVersionListSerializer` — leaks cloud credentials [RESOLVED]

**File:** `backend/documents/serializers.py` → `DocumentVersionListSerializer`

Per `plans/cloud-import-enhancements.md`, the `metadata` JSONField stores:
```json
{
  "cloud_import": {
    "connection_id": 12,
    "file_id": "id:abcdef12345",
    "etag_or_rev": "015d30000000000000000"
  }
}
```
`connection_id` is a Hashid-encoded foreign key to a `CloudConnection` (which stores OAuth tokens). `etag_or_rev` is a provider-level revision ID. These are internal identifiers — exposing them raw to the version list API endpoint reveals implementation internals and potential IDOR vectors.

**Fix:** Either drop `metadata` from the list serializer or expose only a filtered safe subset:
```python
# Option A: exclude entirely
fields = ['id', 'version_number', 'file_size', 'num_pages',
          'is_primary', 'has_pages', 'render_status', 'render_error', 'created_at']

# Option B: filtered method field
cloud_import_source = serializers.SerializerMethodField()

def get_cloud_import_source(self, obj):
    ci = (obj.metadata or {}).get('cloud_import', {})
    return ci.get('provider_display') if ci else None
```

#### 5. `preview-data` with `?version_id` bypasses document readiness check [RESOLVED]

**File:** `backend/documents/views.py` → `DocumentPreviewDataView`

```python
if not version_id and document.status != 'ready':
    return Response({"detail": "Document is not ready for preview."}, ...)
```

When `version_id` is provided, the document status check is skipped entirely. A user could call `GET /preview-data/?version_id=<any_valid_id>` on a document in `processing`, `uploading`, or `error` state. Per the plan's intent, this path is for previewing older inactive versions — the document itself should still be accessible.

**Fix:** Distinguish between document-is-inaccessible (e.g. `uploading`) and document-is-broken (e.g. `error`) when `version_id` is present:
```python
if version_id:
    if document.status == 'uploading':
        return Response({"detail": "Document is not ready."}, status=400)
    # allow preview of specific version regardless of primary status
elif document.status != 'ready':
    return Response({"detail": "Document is not ready for preview."}, status=400)
```

## 📋 Proposed Additions to Long-Term Memory

The following new prevention rules were surfaced during this review. **Should I commit these to `docs/tech_stack_guidelines.md`?**

```
[ ] Issue: `promote_document_version` read `old_file_size` from the un-locked `document` object before acquiring `select_for_update()`, creating a quota-check race condition.
    Prevention Rule: Always acquire `select_for_update()` lock before reading any field used in a quota or concurrency-sensitive check. Read all relevant values from `locked_doc`, not from the argument passed to the function.

[ ] Issue: `DocumentVersionListSerializer` exposed the raw `metadata` JSONField, which contains cloud provider `connection_id` and `etag_or_rev` values intended as private implementation data.
    Prevention Rule: Never include JSONFields that store cloud provider internals in public-facing list serializers. Either exclude them or expose only a filtered, display-safe subset via a SerializerMethodField.

[ ] Issue: `version_id` query/body parameter passed directly to `get_object_or_404` without integer validation — a non-numeric string raises ValueError (500) instead of a clean 400.
    Prevention Rule: Validate and cast any PK parameter from request.data or request.query_params to `int` before using it in an ORM lookup. Return a 400 response on cast failure.

[ ] Issue: Promoting the currently-primary version was not blocked, violating the plan's acceptance criteria ("cannot be promoted again").
    Prevention Rule: When implementing a state-change action (promote, activate, publish), always add an early guard that rejects a no-op or invalid transition, and add a unit test for that boundary case before writing the guard (TDD).
```
